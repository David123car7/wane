# API documentation

## Decision

The HTTP API is documented with Scalar. The OpenAPI document is generated by ASP.NET Core itself (`Microsoft.AspNetCore.OpenApi`) from the controllers and DTOs, and Scalar renders it as an interactive page where endpoints can be read and tried.

Nothing is written by hand: the document comes from the code. Descriptions come from the XML documentation comments on the controllers and DTOs, and validation rules come from the data annotations on the DTOs (see `validation-and-mapping.md`).

The OpenAPI and Scalar setup is registered by `Wane.Host`, the composition root (see `onion-architecture.md`). The controllers in `Wane.Api` stay free of documentation tooling.

## Why

Scalar is a modern interface for the OpenAPI document, actively maintained, and easy to wire into ASP.NET Core. The built-in OpenAPI generation means no extra generator package, and the spec cannot drift from the code, because it is produced from it. A frontend or any other client gets a contract to work from, which is what `proposal.md` asks for.

## Possible change: Swagger UI

Swagger UI could render the same OpenAPI document instead of Scalar.
- Pros: the best known option, with the most examples online.
- Cons: a dated interface, and it would need an extra package.

Because the document is generated separately from the interface, switching later only changes the UI registration in the Host.
